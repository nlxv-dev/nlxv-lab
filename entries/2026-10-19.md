# NLXV Lab / Devlog & Changelog

*Timeline: October 19, 2026*

## Project 02 --- Neo Finance

### v2.9.5 --- Themes & Amount Input Update

The day's work covered the completion of the theme system and the
implementation of a dedicated internal numeric input experience for
monetary values.

------------------------------------------------------------------------

### Stage 1 --- Themes & Initialization

#### Theme System

-   Completed support for **System**, **Light**, and **Dark** appearance
    modes.
-   Added system appearance detection.
-   Added persisted theme-state loading before the first interface
    render.
-   Removed the initial theme flash during application startup.
-   Preserved the selected appearance across PWA restarts.
-   Updated the theme control to reflect the **currently active mode**
    instead of always displaying the System icon.

#### Theme Menu

-   Added a dedicated appearance-selection pop-up.
-   Added separate entries for System, Light, and Dark modes.
-   Added icons and labels for each appearance mode.
-   Refined the menu dimensions and internal spacing for mobile use.
-   Reduced unnecessary empty space inside the menu.
-   Kept the current appearance visually identifiable from the main
    theme control.

------------------------------------------------------------------------

### Stage 2 --- Internal Amount Keyboard

#### Amount Input

-   Added a dedicated `AmountKeyboard` component for monetary input.
-   Implemented digit input from `0` to `9`.
-   Removed decimal separators from the monetary input flow.
-   Removed arithmetic operators from the keyboard.
-   Added deletion of the last entered digit.
-   Added long-press clearing through the Backspace control.
-   Added shared amount-processing logic outside the visual keyboard
    component.

#### Keyboard Layout

-   Implemented a standard three-column numeric layout.
-   Centered `0` below `8`.
-   Kept Backspace in the right-hand position of the bottom row.
-   Removed the additional visual tile behind Backspace.
-   Adjusted spacing and touch areas for mobile use.

#### Input Mode

-   Added a dedicated active amount-input state.
-   Kept the amount visible while the keyboard is open.
-   Temporarily hid secondary form information during active input.
-   Reduced unnecessary vertical space between the amount, action
    control, and keyboard.
-   Added a muted `0` placeholder for an empty amount.
-   Removed the currency symbol from the active new-transaction amount
    display to preserve visual symmetry.

#### Keyboard Controls

-   Added keyboard opening through interaction with the amount.
-   Added keyboard dismissal through repeated tapping of the active
    amount.
-   Preserved dismissal through interaction outside the input area.
-   Added downward-swipe dismissal.
-   Kept keyboard behavior consistent across supported monetary flows.

------------------------------------------------------------------------

### Integration

The internal amount keyboard was integrated into:

-   New transaction creation.
-   Transaction editing.
-   Balance adjustment.
-   Monthly budget editing.

A single keyboard implementation is reused across these flows to keep
input behavior consistent throughout the application.

------------------------------------------------------------------------

### Technical Cleanup

-   Fixed the `react-refresh/only-export-components` warning caused by
    mixed exports in `AmountKeyboard.tsx`.
-   Moved shared amount-input logic outside the visual keyboard
    component.
-   Corrected the keyboard state setter typing in
    `TransactionDetailSheet.tsx`.
-   Fixed `AddTransactionSheet` import/export compatibility in
    `App.tsx`.
-   Preserved reusable component boundaries for the monetary input
    system.

------------------------------------------------------------------------

## End Result

-   **Theme system:** System, Light, and Dark modes are now initialized
    and represented consistently.
-   **Amount input:** Neo Finance now uses a dedicated internal numeric
    input experience for its main monetary forms.
-   **Consistency:** Transaction creation, transaction editing, balance
    adjustment, and budget editing share the same amount-input behavior.
-   **UX foundation:** The amount-input flow is now prepared for the
    animation and interaction polish planned for the next development
    stage.

### Next Stage

**Stage 3 --- Animations**

The next stage will focus on integrating Motion for:

-   keyboard appearance and dismissal;
-   amount movement;
-   sheet transitions;
-   state changes;
-   value transitions;
-   micro-interactions and tactile feedback.

# NLXV Lab / Девлог и список изменений

*Хронология: 19 октября 2026*

## Проект 02 --- Neo Finance

### v2.9.5 --- Темы и внутренний ввод сумм

Работа за день была сосредоточена на завершении системы тем и реализации
отдельного внутреннего интерфейса ввода денежных значений.

------------------------------------------------------------------------

### Этап 1 --- Темы и инициализация

#### Система тем

-   Завершена поддержка режимов **Системная**, **Светлая** и **Тёмная**.
-   Добавлено определение системного режима отображения.
-   Реализовано чтение сохранённого состояния темы до первого
    отображения интерфейса.
-   Устранено первоначальное промаргивание темы при запуске приложения.
-   Сохранение выбранного режима сохраняется после повторного запуска
    PWA.
-   Кнопка выбора темы теперь отображает **фактически активный режим**,
    а не всегда иконку системной темы.

#### Меню выбора темы

-   Добавлено отдельное выпадающее меню выбора режима отображения.
-   Добавлены отдельные пункты для системной, светлой и тёмной темы.
-   Для каждого режима добавлены иконка и подпись.
-   Скорректированы размеры и внутренние отступы меню для мобильного
    интерфейса.
-   Уменьшено избыточное пустое пространство внутри меню.
-   Сохранена визуальная индикация текущего режима непосредственно в
    основной кнопке выбора темы.

------------------------------------------------------------------------

### Этап 2 --- Внутренняя клавиатура для денежных значений

#### Ввод сумм

-   Добавлен отдельный компонент `AmountKeyboard` для ввода денежных
    значений.
-   Реализован ввод цифр от `0` до `9`.
-   Десятичный разделитель исключён из сценария денежного ввода.
-   Арифметические операторы исключены из клавиатуры.
-   Реализовано удаление последней введённой цифры.
-   Добавлена очистка значения длительным нажатием Backspace.
-   Общая логика обработки денежных значений вынесена за пределы
    визуального компонента клавиатуры.

#### Раскладка клавиатуры

-   Реализована стандартная трёхколоночная цифровая сетка.
-   Клавиша `0` размещена по центру под `8`.
-   Backspace оставлен в правой позиции нижнего ряда.
-   Дополнительная визуальная плитка вокруг Backspace удалена.
-   Скорректированы расстояния и области нажатия для мобильного
    использования.

#### Режим ввода

-   Добавлено отдельное активное состояние ввода суммы.
-   Значение суммы сохраняется видимым при открытой клавиатуре.
-   Второстепенная информация формы временно скрывается во время
    активного ввода.
-   Уменьшено избыточное вертикальное пространство между суммой,
    управляющей кнопкой и клавиатурой.
-   Для пустого значения добавлен приглушённый `0`.
-   Символ валюты удалён из активного поля новой транзакции для
    сохранения визуальной симметрии.

#### Управление клавиатурой

-   Реализовано открытие клавиатуры через взаимодействие с суммой.
-   Добавлено закрытие клавиатуры повторным нажатием на активную сумму.
-   Сохранено закрытие при взаимодействии с областью вне ввода.
-   Добавлено закрытие свайпом вниз.
-   Поведение клавиатуры унифицировано для всех поддерживаемых денежных
    сценариев.

------------------------------------------------------------------------

### Интеграция

Внутренняя клавиатура подключена к следующим сценариям:

-   Добавление новой транзакции.
-   Редактирование транзакции.
-   Корректировка баланса.
-   Редактирование месячного бюджета.

Один компонент клавиатуры используется во всех перечисленных сценариях,
что обеспечивает единое поведение денежного ввода во всём приложении.

------------------------------------------------------------------------

### Техническая шлифовка

-   Исправлено предупреждение `react-refresh/only-export-components`,
    связанное со смешанными экспортами в `AmountKeyboard.tsx`.
-   Общая логика обработки денежных значений вынесена из визуального
    компонента клавиатуры.
-   Исправлена типизация setter-функции состояния клавиатуры в
    `TransactionDetailSheet.tsx`.
-   Исправлена совместимость импорта и экспорта `AddTransactionSheet` в
    `App.tsx`.
-   Сохранено разделение компонентов и повторное использование общей
    системы денежного ввода.

------------------------------------------------------------------------

## Итог

-   **Система тем:** режимы Системная, Светлая и Тёмная теперь корректно
    инициализируются и отображаются согласованно.
-   **Ввод сумм:** в Neo Finance реализован отдельный внутренний
    интерфейс цифрового ввода для основных денежных форм.
-   **Единое поведение:** создание и редактирование транзакций,
    корректировка баланса и изменение бюджета используют одну механику
    денежного ввода.
-   **UX-фундамент:** интерфейс денежного ввода подготовлен к
    последующей анимационной и интерактивной полировке.
